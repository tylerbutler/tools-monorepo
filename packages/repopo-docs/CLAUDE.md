# CLAUDE.md - repopo-docs

Package-specific guidance for the Repopo documentation site.

## Package Overview

Documentation website for the Repopo repository policy enforcement tool, built with Astro and Starlight.
It is the source of truth for repopo's user documentation; `packages/repopo/README.md` only has a quick
start and links here.

**Framework:** Astro (static output) with the Starlight theme
**Deployment:** Cloudflare Workers Static Assets (`wrangler.jsonc`), at https://repopo.tylerbutler.com.
See `README.md` for build, preview, and deployment commands.

## Essential Commands

```bash
# Build the site (from the monorepo root; also builds repopo and generates API docs)
pnpm exec nx run repopo-docs:build:site

# Dev server with hot reload (http://localhost:4321)
pnpm --filter repopo-docs dev

# Type-check Astro content and config
pnpm nx run repopo-docs:check:astro
```

## Project Structure

```
packages/repopo-docs/
├── src/content/docs/
│   ├── index.mdx            # Homepage (splash template)
│   ├── introduction.mdx     # "Start Here" pages
│   ├── installation.mdx
│   ├── usage/               # Guides: CLI usage, config, programmatic API, benchmarking
│   ├── policies/            # built-in overview, one page per ecosystem, custom policies
│   ├── cli-reference.md     # GENERATED by repopo's `readme:docs` script
│   └── api/                 # GENERATED by starlight-typedoc
├── src/assets/, src/styles/
├── astro.config.mjs         # Sidebar, Starlight plugins, redirects
└── wrangler.jsonc           # Cloudflare deployment
```

The "Guides" and "Policies" sidebar groups are autogenerated from their directories. Set page order
with `sidebar.order` in frontmatter. "Start Here" and "CLI Reference" are listed explicitly in
`astro.config.mjs`.

## Generated Content

Do not hand-edit generated files:

- **`api/**`**: starlight-typedoc generates these from `../repopo/src/index.ts` during `build:site`.
  Change the TSDoc in repopo's source instead, then rebuild and commit the regenerated files.
- **`cli-reference.md`**: `pnpm nx run repopo:build:readme` regenerates the content between the
  `<!-- commands -->` markers from the oclif command definitions. oclif needs the file to exist and
  edits it in place. repopo's `package.json` therefore lists it as both an input and an output of
  `build:readme`, so edits to it are hashed and cache hits restore it.

## Policy Documentation

Built-in policies are documented on four pages, grouped by ecosystem:

| Page | Policies |
| --- | --- |
| `policies/javascript.mdx` | File headers, `NoJsFileExtensions`, `Package*`, script policies |
| `policies/rust.mdx` | `Cargo*`, `Rust*`, `Workspace*`, other Rust/Cargo policies |
| `policies/gleam.mdx` | `Gleam*`, `NoBuildDirectory` |
| `policies/repository.mdx` | Ecosystem-neutral policies |

`policies/built-in.mdx` has the default policies, configuration examples, and a table of every policy
with its scope and fix support.

When adding or changing a policy in `packages/repopo/src/policies/`:

1. Add or update its `### PolicyName` section on the right page. Use the facts in the source: its TSDoc,
   the `*Config` interface and `@defaultValue` tags, the `match` regex, and whether it fixes violations.
2. Add or update its row in the matching table in `policies/built-in.mdx`.
3. Every policy exported from `src/policies.ts` must appear exactly once as a `###` heading.

Policy entries follow this shape. Configuration examples use `policy()`, not the legacy `makePolicy()`,
and exclusions are regular expressions passed as the third argument:

````markdown
### NoJsFileExtensions

Reports JavaScript files that use the `.js` extension. ...

```ts
policy(NoJsFileExtensions, undefined, { exclude: ["^bin/"] });
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |

**Auto-fixable:** No.
````

## Starlight Plugins

- `starlight-typedoc`: API reference generation (configured in `astro.config.mjs`).
- `starlight-package-managers`: the `<PackageManagers pkg="repopo" />` component renders install
  commands for each package manager (see `installation.mdx`).
- `starlight-links-validator`: installed but **disabled** in `astro.config.mjs` until known problems are
  fixed, so the build does not catch broken links or anchors. Check them in the built `dist/` HTML.

## Important Constraints

1. **Part of the monorepo**: depends on `repopo` via `workspace:^`.
2. **Static site**: `output: "static"`; no server adapter.
3. **Links**: use root-relative links with a trailing slash (`/policies/built-in/`). The generated API
   readme lives at `/api/readme/`.
