You can run policies from your own code as well as from the CLI. repopo has three entry points:

| Import | Contents |
| --- | --- |
| `repopo/api` | Policy types, `policy()` and the policy definers, adapters, and `PolicyRunner`. |
| `repopo/policies` | The [built-in policies](/policies/built-in/) and their configuration types. |
| `repopo` | Everything in `repopo/api`, plus the CLI's `run` function from OCLIF. |

Import from `repopo/api` in programs so you don't load the CLI entry point.

## Running policies

`PolicyRunner.run()` returns an [Effection](https://frontside.com/effection) operation. Run it with `run` from `effection`:

```ts
import { run } from "effection";
import { PolicyRunner, policy } from "repopo/api";
import { NoJsFileExtensions } from "repopo/policies";

const runner = new PolicyRunner({
	policies: [policy(NoJsFileExtensions)],
	gitRoot: process.cwd(),
	resolve: false,
	excludeFromAll: [],
	excludePoliciesForFiles: new Map(),
});

const { results } = await run(() => runner.run(["src/main.mjs"]));
```

### Runner options

| Option | Description |
| --- | --- |
| `policies` | Configured file and repository policies. |
| `gitRoot` | Absolute path of the repository root. |
| `resolve` | `true` to apply fixes, like `check --fix`. |
| `excludeFromAll` | Regular expressions that exclude repo-relative paths from every policy. |
| `excludePoliciesForFiles` | Per-instance exclusions. Entries override a policy's own exclusions. |
| `concurrency` | Maximum files processed at once in read-only runs. Defaults to 8. Fixes always run one at a time. |
| `logger` | Optional logger for file-exclusion messages. |

### Selected files and the repository inventory

`run(filePaths, repositoryFiles)` takes two lists:

- `filePaths`: the repo-relative files that file policies check.
- `repositoryFiles`: the full inventory that repository policies receive.

```ts
await run(() => runner.run(selectedFiles, repositoryFiles));
```

If `repositoryFiles` is omitted, the runner uses `filePaths`, which is correct only when you check the whole repository. When fixes can create or remove files, pass an async function that returns the inventory instead of an array. The runner calls it again before each repository policy.

### Results

`run` returns `{ results, perfStats }`. Each result has a `scope`, the `policy` name, the `policyId`, and an `outcome`. File results also have the `file`, and a `resolution` when a standalone resolver ran.

Use the `isPolicyError`, `isPolicyFailure`, and `isPolicyFixResult` type guards to tell outcome shapes apart.

## Standalone resolvers

A file policy can provide its fix as a separate `resolver` instead of fixing in the handler. See [Standalone file resolvers](/policies/custom/#standalone-file-resolvers). `PolicyRunner` converts every resolver result to a `PolicyFixResult` in the `resolution` field of the file result.

See the [API reference](/api/readme/) for every exported type and function.
